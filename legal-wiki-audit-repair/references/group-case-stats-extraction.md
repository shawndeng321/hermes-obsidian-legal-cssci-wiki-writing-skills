# 群案统计提取流水线（STATS-EXTRACT模式，2026-08实测）

场景：从案例库（如121案）批量提取裁判结果做统计（改判率/认定率/年代切片/检察介入率），供论文"实证数据切入"与引注矩阵填充使用。

## 步骤

1. **提取**：脚本遍历 `entities/案例/` 三子目录，正则抓取 `## 程序历程与裁判结果` 段落（无此节的页用变体节：`## 诉讼程序与裁判观点`/`## 诉讼程序与原审裁判`+`## 抗诉与监督结果` 合并；抓取边界 = 下一个 `\n## ` 或 `\n---` 或 EOF）。同时从文件名正则 `^案例(\d+)-(\d{4}|年份不详)-` 提取编号与年份，从目录名提取层级（核心/辅助/参考）。输出 JSON。
2. **人工归类**（不能纯脚本判断，叙述文本格式不统一）：把 JSON dump 成 `[num|year|layer] 文本` 行、分批通读，逐案标三类维度：
   - 最终结果：`Y`支持工伤（认定/维持认定/撤销不予认定/撤销责令重作）/ `N`不支持（维持不予认定/驳回诉请）/ `P`程序性或待遇类（不予受理撤销、中止、非诉执行、待遇给付）/ `O`其他（民事协议纠纷等，剔除出认定率分母）；
   - 行政-司法关系：`一致`/`改判`/`NA`（改判=法院最终裁判与原行政决定不一致）；
   - `检察介入` 0/1（抗诉/检察建议/监督化解）。
3. **Python汇总**：结果分布、支持率（Y/实体样本）、改判率（改判/有行政决定样本）、年代切片（剔除年份不详）、分层统计（核心62 vs 辅助17 vs 参考42）、检察介入数、改判方向（支持性 vs 反向）。分类表存 JSON 供复用。
4. **口径先确认**：归类维度定义（尤其"改判"是否含程序性撤销、撤销重作是否并入认定）先给用户确认再定稿；**计算前先查引注矩阵是否已有定稿统计**——多会话协作时另一会话可能已算过（实测：写作会话算得45.7%，原会话定稿41.3%，差异=撤销重作是否单列+程序性撤销是否计入，以用户确认版为准）。

## 关键坑

- 案例页 `## 程序历程与裁判结果` 是叙述文本（"驳回上诉、维持原判"等），正则只能提取不能分类，必须人工/LLM通读归类；全量约1.4万字可分2批读完。
- 个别页面无 `程序历程` 节（检例205号、检例236号本体页用变体章节名），先 grep `^## ` 确认实际节名再补提。
- 反向改判案（行政认定工伤→法院撤销，如案例20/47）在"撤销重作"计数里会被吞成支持性改判——统计改判方向时必须单独挑出，否则"偏差源头在行政端"的论证会被反向数据削弱。
- 样本性质：精选汇编非随机抽样，百分比只作"样本内"表述；年代切片早期段样本量过小（如7案）时不谈趋势。
