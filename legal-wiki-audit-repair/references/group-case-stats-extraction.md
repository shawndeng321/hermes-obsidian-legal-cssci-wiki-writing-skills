# 群案统计提取流水线

用于从案例库批量提取裁判结果并统计（结果分布、改判率、年代切片、分层比较、特定程序介入率），供论文实证切入和论点—证据—引注矩阵使用。口径与表述限制见 `legal-research-wiki` 的 `references/statistics-landing-and-case-matching.md`。

## 步骤

1. **提取**：脚本递归遍历 `entities/案例/`，抓取“程序历程与裁判结果”章节（没有此节的页面，先 `grep '^## '` 确认实际章节名，合并其变体章节）；边界为下一个 `\n## `、`\n---` 或文件末尾。同时从文件名 `^案例(\d+)-(\d{4}|年份不详)-` 取编号与年份，从子目录名取分层。输出 JSON。
2. **逐案归类**：叙述文本（“驳回上诉、维持原判”等）格式不统一，正则只能提取不能分类。把 JSON 转成 `[编号|年份|分层] 文本` 行分批通读，按**用户确认的口径**标注：
   - 最终结果类别（例如：支持 / 不支持 / 程序性或给付类 / 其他——“其他”剔除出分母）；
   - 行政与司法是否一致（一致 / 改判 / 不适用）；
   - 研究关心的其他维度（例如是否有检察监督介入）。
3. **汇总**：结果分布、支持率（按定稿分母）、改判率、年代切片（剔除年份不详）、分层统计、特定维度计数、**改判方向**。分类表存 JSON 以便复核。
4. **口径先确认**：归类维度的定义先交用户确认；**计算前先查矩阵中是否已有定稿统计**，多会话协作时另一会话可能已算过。两套结果不同时，先找出差异来源（例如撤销重作是否单列、程序性撤销是否计入），以用户确认的版本为准。

## 关键坑

- 反向改判（行政机关支持、法院撤销）会在“撤销”计数里被算成与主流方向相同的改判；统计改判方向时单独挑出，否则论证方向会被数据削弱；
- 精选汇编不是随机样本，百分比只作“样本内”表述；某时间段样本极少时不谈趋势；
- 案例页结果字段落地后，用脚本全量重算并与人工口径交叉核对，差异逐项归因，不直接改定稿数字。
