# DOCX范围核验与既有案例页面映射

## 适用场景

当用户提供一个声称包含若干指导性案例、判决书或案例全文的DOCX，并要求更新已有案例Wiki时使用。尤其适用于：

- 文件名中的案例数量可能与正文实际数量不一致；
- 文档同时包含相关案例与无关案例；
- Wiki中已经存在由简编或摘要生成的案例页，需要用更完整材料补充；
- 批量更新可能影响10个以上既有页面。

## 1. 先解析实际文件，不相信文件名和用户概括中的数量

1. 先用文件搜索确认用户给出的实际路径。中文目录名、括号和文件名经常被用户描述合并，不能把描述直接拼接成路径。
2. 确认文件存在后，记录文件大小、文档总段落数、非空段落数、表格数和正文文本长度。
3. 优先使用 `python-docx` 读取；如果读取库无法工作，使用标准库进行只读解析：

```python
from zipfile import ZipFile
from xml.etree import ElementTree as ET

with ZipFile(src) as z:
    xml = z.read("word/document.xml")
root = ET.fromstring(xml)
# 遍历 w:body 下的 w:p，拼接 w:t；同时统计表格和非空段落
```

4. 不能因为文件名写着“26个案例”就报告已经读取了26个。必须根据正文中的 `检例第X号`、`指导性案例第X号`、案例标题或明确编号统计实际条目。
5. 如果正文数量与文件名不符，立即记录差异，并以正文实际内容为准。不要凭空补齐缺失案例。

## 2. 识别案例边界和全文结构

对非空段落逐段扫描，识别以下字段或标记：

- 案例编号、案例标题；
- `【关键词】`、`【要旨】`、`【基本案情】`；
- `【检察机关履职过程】`、`【裁判结果】`、`【指导意义】`；
- `【相关规定】`或规范依据；
- 办案检察院、承办检察官等来源信息。

不要只依赖Word标题样式：很多汇编把所有段落都设为普通正文。应以文本标记和案例编号建立区块边界。对每个区块保存起止段落位置和完整原文，便于回溯。

## 3. 建立案例—既有页面映射

将每个源案例分为四类：

1. **精确匹配**：检例编号、案名或当事人组合与既有页面一致；在原页面更新，不新建重复页。
2. **可确认的名称变体**：案名有空格、匿名符号、法院简称差异，但案号和事实能够确认；记录匹配依据后更新原页。
3. **源文档中的新相关案例**：与研究主题相关但Wiki没有对应页；先报告拟新建页面名称和数量，批量新建前确认范围。
4. **无关或超出研究范围的案例**：例如同一汇编中与本项目主题无关的其他领域案件；不纳入本库，但在结果中说明排除理由。

映射报告至少列出：源案例编号、准确案名、匹配的现有文件、处理动作（更新/新建/排除）和理由。

## 4. 批量修改前的范围纪律

- 如果预计修改10个以上既有页面，即使用户说“全部更新”，也要先完成映射并报告受影响页面、修改字段和预计新增页面数量，再开始批量写入。
- 如果实际匹配数量少于文件名暗示的数量，应明确报告“实际更新了多少个”，不能把目录数量当作完成数量。
- 只有在范围清楚、页面映射完成后，才复制原始DOCX到Wiki的 `raw/cases/` 并更新实体页来源。

## 5. 既有案例页的细化标准

使用完整材料更新原页面时，不要只把“简化案情”替换成一段更长的文字。至少检查并补充：

- 基本信息：检例编号、发布批次、日期、法院/机关、案号匿名状态；
- 基本案情：人物、劳动关系、时间、地点、工作任务、受伤或死亡经过；
- 程序时间线：行政认定、复议、民事程序、行政诉讼、再审、抗诉和监督结果；
- 争议焦点：把事实争议、证据争议、法律适用争议和程序争议分开；
- 行政机关、法院、检察机关各自的观点；
- 裁判结果和裁判要旨；
- 指导意义或规范意义；
- 相关规范及条文号；
- 在研究设计分析框架中的定位（按本项目确认的维度）；
- 与底稿、概念页、引用论文和其他案例的双向链接。

事实、日期、金额和程序结果只能来自源文档。研究性分析要和源事实分开写在“研究定位”或“与底稿的关联”中，不要把推论伪装成裁判原文。

## 6. 完成后的验证

每批更新后至少验证：

- raw/cases中的原始文件确实存在，页面 `sources:` 与实际路径一致；
- 每个受影响页面都有基本案情、程序历程、裁判要旨、指导意义、规范依据和研究定位；
- 页面不是空壳，且没有“详见原文”“待补充”等占位符；
- 所有 `[[wikilinks]]`目标存在，死链接为零；
- index.md仍列出全部正式页面；
- 不相关案例没有被误写进本项目研究；
- 最终报告列出准确的更新页面清单，并单独说明被排除的源条目和原因。

## 参考

本流程源自一次实际核验：文件名声称包含 26 个指导性案例，正文实际只有 3 个，其中 1 个与研究主题无关。最终只更新了 2 个已有案例页，并把数量差异和排除理由写入日志。
