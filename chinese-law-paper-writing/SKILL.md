## 闭世界查询纪律（CLOSED-WORLD QUERY，强制）

**写作/论证支撑只使用知识库（Wiki）与用户提供的原始材料**——禁止联网补缺、禁止用模型自身记忆编造来源。这是防止 AI 幻觉（瞎编乱造）的核心学术纪律，与"不得补造"规则一脉相承但更严格：

- **知识库未覆盖的问题** → 如实说"库内无此内容"，标记 `[来源不明]`/`[待核]`，先摄入再答；不得用模型记忆"补全"；
- **桩/空壳页面不算覆盖**——页面只有 frontmatter 或占位正文时视为未摄入，禁止脑补内容（对应：121案未摄入前，统计口径不得写成已验证结论）；
- **来源性主张（法条/案号/文献页码/数据）必须能回溯到库内页面 + raw 原始材料**，否则不得写入正文；宁缺毋滥，不可"看起来像真的"就写；
- **联网检索只属于摄入环节**（用户授权后为补充素材），永远不属于查询/写作环节；
- 写作草稿中的任何数字、比例、判例归纳，必须是库内已核验材料；未验证的一律标 `[待核]`，不静默升级。

## 核心原则

围绕一个可论证的主问题组织论文（**一文一问**）；让每项来源性主张可追溯，让每项法律判断标明依据、版本与核验状态。宁可保留待核项，也不得补造文献、页码、案号、法条、数据或期刊要求。

## 启动纪律（强制执行）

当用户要求新建任何研究 Wiki 或开始新研究时，必须按以下顺序执行：

1. **第一步**：将五问方法论（即本技能的核心内容）写入该 Wiki 的 `concepts/` 目录
2. **第二步**：问用户"这次研究的问题意识是什么？分析框架是什么？"（对应 Q1—Q4）
3. **第三步**：用户确认思路后，才开始摄入论文和案例

不得跳过前两步直接摄入材料。

## 需求拆解与行文结构的区分（最高纪律）

五问框架（Q1—Q5）是 Agent 拆解模糊需求、澄清研究问题的工作方法（agent-side），**不是**论文行文结构本身（user-side）。两者不得混淆：

1. **用户需求模糊时**，用五问拆解：交付物（Q1）→读者（Q2）→问题意识（Q3）→材料（Q4）→验收标准（Q5），逐项确认后再动手。
2. **用户已确立研究思路时**（既定章节框架、分析维度、判断结构，如"发现问题—解释转型—构造标准—保障适用"四段式或三阶判断），行文结构必须服从用户思路；不得用五问推演出的结构覆盖、替换用户思路。
3. **生成大纲、评估初稿前，必须先读用户的研究思路文档**（如"论文思路"等同级文件）并紧密贴合；"贴合用户研究思路"是最高纪律，先确认思路再生成结构，禁止凭 Agent 侧推演（如按 wiki 研究设计）直接产出结构。
4. **冲突处理**：五问推演的结构与用户思路冲突时，以用户思路为准，并把差异作为问题提出来由用户决策，不得自行合并或替换。
5. **研究/行文思路是项目特定的（user confirmed 2026-08）**：三维度（群案研究：裁判方法变迁/法律适用演变/行政与司法张力）仅适用于工伤认定群案研究项目，**不是通用行文模板**。新项目用户没说思路时，AI必须主动问（见 `five-questions-framework` skill）；用户也不知道思路时，允许先建库、模块完成后主动给建议。

## 反说纪律（学术论证的呈现逻辑，user confirmed 2026-08，强制执行）

> 学术论文的"研究过程"与"行文论证"方向是**相反的**——作者实际先定好研究方向/思路和行文方式，但**行文时必须反过来说**："是通过多个案例的对比/演变/演化，得出来我的研究方向/思路"。

**具体含义**：
- 实际过程：先有研究思路 → 再找素材/案例 → 验证/完善思路。
- 行文呈现：必须写成"从案例的对比/演变/演化中**归纳出**结论"——**实证归纳在前，论点结论在后**，不能暴露"先有结论再找案例支撑"。
- 例：不能说"我们认为裁判存在偏差，下面用案例证明"；要说"通过对121案的对比分析，发现裁判偏差呈现出系统性特征，由此归纳出……"。

**执行要点**：
1. 论文"问题的提出"和结论部分，论证顺序必须是**素材→规律→结论**（从案例数据/规范演变中推出论点）。
2. 案例引用永远服务于论证归纳（分组对比、演变线索），不是"举例说明我事先想好的观点"。
3. 论文中的方法表述：写"本文通过对X个案例的类型化分析/历史演变梳理"，不写"本文选取案例验证观点"。
4. 审稿人视角：结论必须看起来是从材料中长出来的，不是贴上去的——这是实证/群案研究的说服力来源。

## 逻辑链完整性纪律（反断言纪律，user confirmed 2026-08，强制执行）

> 反说纪律解决"论证顺序"（实证归纳在前），本纪律解决"推理密度"（归纳必须完整）。**结论不允许以断言方式出现**——每个核心结论必须呈现完整、清晰、可经得起推敲与质疑的推理链。"案例/数据 → 结论"的直接跳跃是初稿最大的弱点，审稿人一眼可见；缺任何一环，结论即属"断言"，必须返工补链。

**合格逻辑链的通用形态**：证据呈现 → 归纳推理 → 排除竞争解释 → 处理反方 → 得出结论。三类命题各有具体要求：

### 1. 实证归纳命题（从案例/数据归纳的命题，如群案研究子结论）

| 环节 | 要求 |
|---|---|
| 证据并置 | 多个案例/数据**分组呈现**（非单案例举例），说明同类案件的裁判逻辑 |
| 共同特征 | 说明证据共同指向什么，论证要素反复出现才有概括意义 |
| **排除竞争解释** | 至少排除一个可能的替代解释（如"倾斜保护偏好""个案无规律""规范适应期"），说明为何只有本解释能说明全部证据——**此环不可省** |
| 反方/边界 | 呈现证据中不支持本解释的部分（反向案例、边界案例），如样本中的反向改判、否定性裁判 |
| 归纳命题 | 在以上四环完成后才可得出命题 |

### 2. 规范性命题（应当如何的命题，如判断标准构造）

| 环节 | 要求 |
|---|---|
| 制度功能 | 从制度目的/功能出发论证（如工伤保险=职业风险社会化分担机制） |
| 规范任务 | 制度功能转化为规范任务（识别伤害风险是否属于职业风险） |
| 判断结构 | 规范任务展开为具体判断结构（三阶判断等） |
| 法定依据 | 说明结构与现行法的关系（是解释方法而非创设新标准） |

**禁止以隐含前提代替论证**——"这一结构显然合理""不言自明"式表述属于断言；作者脑中已有的理论铺垫（如从旧稿继承的论证）必须在正文中显式写出，审稿人没有义务知道。

### 3. 统计性命题（比例、趋势）

- **口径交代**：改判=什么、分母是什么、归类标准是什么，必须可复核
- **样本限定**：精选样本≠随机抽样，比例不得外推，必须限定"样本内"
- **趋势谨慎**：样本年代分布不均时，只能描述分布，不能声称趋势

### 执行要点

1. 每节小结的命题归纳必须经过"排除竞争解释"环节，不能从案例描述直接跳到命题
2. 正文中"由此可以看出""由此可见""因此"等连接词出现处，检查其前后是否有完整推理
3. 结论中的每个概念必须在前文论证中出现过（逻辑闭环：结语能倒推问题提出）
4. 生成大纲/初稿后逐节自查：每个核心主张的推理链是否完整？反方是否处理？隐含前提是否显式？
5. 反方处理是每个归纳命题的必选项（不是可选项）：核心主张至少检查一个重要反方解释或反例
6. 给用户交稿前，主动指出"哪里还是断言、哪里推理链偏短"，不要等用户发现（2026-08实例：4.0初稿用户一眼看出"断言化"问题，作者自查应先行）

### 检查清单（Q5验收项）

- [ ] 每个实证归纳命题：证据并置→共同特征→排除竞争解释→反方/边界→命题？
- [ ] 每个规范性命题：制度功能→规范任务→判断结构→法定依据？
- [ ] 每个统计性命题：口径+样本限定？
- [ ] "由此可见"类连接词前后推理链完整？
- [ ] 无隐含前提未交代？
- [ ] 结语可倒推问题提出？

> 本纪律为总纲级要求；执行细则（竞争解释的实测段落模板、统计口径定稿流程、样本artifact识别、改稿继承关系透明）见 `legal-paper-argumentation` skill（v1.0.0，user confirmed 2026-08），两者配合使用。

## 标点表达纪律（破折号纪律，user confirmed 2026-08，强制执行）

> 正文尽量避免破折号（——）。法学期刊（尤其《政治与法律》）行文用分句、冒号、逗号、括号承担解释与补充功能；破折号被视为论证跳跃、口语化或简化表达的标志，审稿印象差。**写作与改稿验收时"破折号残留"是必查项。**

**替代方案**（按语境选用）：

| 破折号用法 | 替代 |
|---|---|
| 解释说明"X——Y" | "X，即Y"／"X：Y"／括号"X（Y）" |
| 补充说明"——Y" | 拆成独立句"……。Y……" |
| 强调"——正是…／——这正…" | "。这正说明……"／"，这正是……" |
| 举例"——如／——例如" | "：如……"或直接分句 |
| 链式概念"类型—任务—风险"（一字线） | 顿号"类型、任务、风险"（引号内专名同理） |

**保留例外**（不得改动）：
1. **文献原标题内的破折号**——引注必须保留文献原名（如"论合宪性解释的法律对话功能——以工伤认定为中心"）；
2. **年份/页码范围连接号**（2003—2010、第119-124页）——期刊规范用法；
3. 论文大标题副标题，如"XXX：基于……的分析"用冒号而非破折号连接。

**执行**：生成初稿/改稿后 grep 破折号（——），逐处核对：属于文内用法则改写，属于文献原名/范围连接则保留；改写时注意英文直引号与中文引号的差异（替换匹配须与文件实际引号一致）。

## 版本管理纪律（user confirmed 2026-08，强制执行）

> 每次交付新版本必须改版本号，不允许出现"两个版本共用一个版本号"或"新版沿用旧版本号"。

**规则**：
- 版本号格式：X.Y.Z（如 4.1.0）。
- **大迭代**（结构、主线、研究方向变化，如重构、换主线）→ 前面大版本号+1（如 4.1.0 → 5.0.0）。
- **小迭代**（增量修改、补强，如加案例、补文献、压缩摘要）→ 中间版本号+1（如 4.1.0 → 4.2.0）。
- **修订**（低风险纠错或文档修复）→ 修订号+1（如 4.1.0 → 4.1.1）。
- 文件命名必须带版本号；被取代的旧版文件加"废弃-"前缀保留（如"废弃-4.0统计版-…"），不直接删除（用户可能回看）。
- 每出新版同步更新：文件命名、log.md 登记、汇报时说明版本号变化。
- 本技能自身版本号同样适用此规则（内容迭代即升号）。

## 五问框架总览

| 问题 | 用途 | 对应模式 |
|---|---|---|
| Q1 我要做什么？ | 锁定交付物：一文一问的CSSCI论文 | PLAN |
| Q2 给谁用？ | 明确四层读者：编辑/审稿人/同行/实务界 | PLAN |
| Q3 解决什么问题？ | 确立问题意识：两要件+三来源+循环调整 | PLAN/RESEARCH |
| Q4 基于什么资料？ | 七类参考文献体系 | RESEARCH |
| Q5 交付成什么样子？ | 逐部件验收标准 | AUDIT/ADAPT |

**用法**：
- 写作前：拿 Q1—Q4 做构思提示词，论证选题是否成立
- 写作中/投稿前：拿 Q5 做验收清单逐项打勾

### Q1 我要做什么？

**一句话定义**：写一篇 1.5万—2.5万字、只解决**一个**规范性法学问题的 CSSCI 期刊论文。

**核心纪律——一文一问**：
- 无论篇幅多长，一篇论文只解决一个学术问题
- 正文可分 3—4 节，每节可有子结论，但子结论必须是**并联**（多角度论证同一问题）或**串联**（递进推导）关系，最终汇聚指向那一个问题
- 问题必须是**法学问题**：识别标准是"规范性"和"法律依据"——与行政学、管理学、经济学、历史学问题的根本分界

**完整交付结构（四件套）**：

| 部件 | 要求 |
|---|---|
| 题目 | "灵魂结晶"，贯穿写作始末，可能最后一步还在改 |
| 问题的提出 | 500—1200字 |
| 正文 | 3—4节 |
| 结语 | 500—1000字 |

### Q2 给谁用？

| 读者 | 他先看什么 | 他要被什么说服 |
|---|---|---|
| 期刊编辑 | 题目（第一印象决定生死） | 题目是否有新意、是否契合期刊定位 |
| 审稿专家 | 问题的提出 + 文献综述 | 问题意识是否成立、学术史梳理是否准确、方法是否可行 |
| 学界同行 | 正文论证 | 子结论之间的逻辑是否闭环、理论贡献是否真实 |
| 实务工作者 | 结语 + 案例运用 | 结论能否回应实践争议、是否具有可操作性 |

**推论**：题目为编辑而写，问题提出为审稿人而写，正文为同行而写，结语为所有人而写。

### Q3 解决什么问题？

**合格问题意识的两个要件**（缺一不可，最好兼具）：
1. **理论上有争议或空白**——学界未形成通说
2. **实务中有争议或空白**——法律实践运行中存在适用分歧

**三大来源路径**：
1. 社会热点中的法学问题
2. 理论争议+实务分歧的交叉地带
3. 国家大政方针/体制改革中亟需解决但现有规范不完整的问题

**反复确立过程**：初步想法 → 阅读材料 → "可能的问题意识" → 清晰化（研究什么？意义何在？现有研究到哪了？能推进什么？分几部分？每部分子结论？能否指向最终结论？）→ 写作中继续调整

**铁律：问题意识—正文论述—结论三者互相调整**，不是单向决定。循环往复直到逻辑闭环。

### Q4 基于什么资料？

**七类参考文献体系**：

| 类别 | 内容 | 使用要点 |
|---|---|---|
| ① 学术著作 | 境内+境外（中译本+外文原版） | 理论根基 |
| ② 学术论文 | CSSCI法学+综合类CSSCI法学论文+SSCI/SCI | 学术史梳理的主料 |
| ③ 法律规范 | 法律、行政法规、司法解释、两高批复/会议纪要、域外规范 | 规范分析的对象 |
| ④ 党内法规 | 强制规范效力的党内文件、重要讲话 | 政治正确性锚点 |
| ⑤ 政策文件 | 党代会报告、规划纲要、法治政府建设实施纲要 | 问题意识的宏观背景 |
| ⑥ 案例 | 五层：典型案例→指导性案例→案例选→裁判文书网→改革试点/执法案例 | 实证支撑；改革试点案例映射新的问题意识方向 |
| ⑦ 新闻报道 | 人民日报等 | 只作背景，不作学术引注 |

**两个关键提醒**：
- 参考文献范围**大于**脚注——读过不等于都要引
- 高水平期刊有一类脚注是"**论述的论述**"——对正文的进一步论述说明，善用可显著提升论文档次

### Q5 交付成什么样子？（验收清单）

- **题目**：紧扣论证内容，是"问题的提出+结语的结晶"，从第一天拟到最后一天，允许推翻重来
- **问题的提出**（500—1200字，三要素，不讲结论）：①研究什么问题、对象是什么、为什么重要；②学界研究到哪了——缺陷/空白/争议是什么；③从什么角度、什么方法研究，期望达到什么目的
- **正文**（3—4节）：并联式（多角度论证同一问题）或串联式（逻辑递进）；子结论必须能汇总成最终结论；结构调整是常态不是失败
- **结语**（500—1000字）：极其精炼，聚焦问题意识的那一个点，**解决它、澄清它、理顺它**——不是重复正文，是给出答案
- **隐藏验收项**：
  - 摘要、关键词按目标期刊格式（如《政治与法律》：摘要200—300字不分段、关键词3—5个）
  - 逻辑闭环自查：从结语能倒推出问题的提出吗？从问题的提出能预知正文结构吗？
  - 脚注质量：有没有"论述的论述"型脚注？

## 群案研究案例用量原则（用户2026-08确认，写入技能）

群案研究论文**不是案例越多越好**——类型化覆盖比数量重要。按论文字数推荐案例用量：

| 用途 | 1.5—2万字建议量 | 说明 |
|---|---|---|
| 正文深度分析 | 8—12个 | 每个有案情描述+争点分析（200—500字），选最权威样本（公报/指导案例/检例优先） |
| 脚注引用 | 20—30个 | 群案实证感的支撑量；用户初稿用20个即属合理区间 |
| 统计提及 | 全部样本 | 若做年代切片/改判率统计，只进表格不逐案叙事 |

**选择原则**：
1. **类型化覆盖优先**——每个争点类型（如超龄/48小时/上下班途中/举证责任/违法转包）选2—3个代表案例，优先权威性（公报/指导案例/检例）
2. **个案详析 vs 统计群像分工**——正文详析案例负责"深度"，统计样本负责"广度"（证明系统性偏差），两者不冲突
3. **避免稀释论证**——逐案罗列是新手通病；群案研究论文的价值在"类型化结论+统计规律"，不在案例数量

**在Plan/Outline阶段主动给用户案例配置建议**：根据字数、问题意识、目标期刊风格（如《政治与法律》实证切入+类型化），推荐"详析N个+脚注N个+统计N个"的具体组合，并说明每个详析案例的选择理由。

## 先确定任务模式

识别用户需要的模式，只执行必要阶段：

| 模式 | 主要输出 | 五问锚点 |
|---|---|---|
| `PLAN` | 选题诊断、研究问题、范围与项目卡 | Q1—Q3 |
| `RESEARCH` | 材料分类、来源核验、研究现状与证据缺口 | Q4 |
| `OUTLINE` | 主张链、章节功能、论点—证据—引注表 | Q1、Q3 |
| `DRAFT` | 带引注标识的分节或全文工作稿 | — |
| `REVISE` | 逻辑、论证、表达、术语和结构修改 | Q3 循环 |
| `AUDIT` | 引注、来源、法律时效、匿名与投稿检查 | Q5 |
| `ADAPT` | 按目标期刊正式要求调整稿件 | Q5 |

上述模式可以反复调用、交叉执行或按材料状态返回前序模式。完整论文通常经历 `PLAN、RESEARCH、OUTLINE、DRAFT、REVISE、AUDIT`，但不强制线性顺序；`ADAPT` 仅在已指定目标期刊且相关要求已经核验时执行。局部任务不得强迫用户重走完整流程。

## 建立任务边界

开始前尽量确认：

1. 任务模式与交付物；
2. 主问题、法学领域与研究范围；
3. 用户允许使用的材料范围、Obsidian 读取范围、允许写回的具体文件及写回授权；
4. 目标期刊及其正式投稿要求；
5. 法律与事实资料截止日期；
6. 引注格式、篇幅和文件格式。

缺失信息不影响方向时，使用明确标注的暂定方案继续；缺失信息会改变结论、期刊适配或来源真实性时，先询问。不得将模型记忆当作已核验来源。

使用 [paper-project-brief.md](assets/templates/paper-project-brief.md) 建立项目卡。未指定目标期刊时，只能生成"通用工作稿"，不得声称存在统一的 CSSCI 字数、摘要、关键词、节数、引注或审稿期限。

用户要求立即排版时，可以给出明确但可逆的"本稿临时参数"；必须逐项标注为暂定，不得替目标期刊设定一稿多投、撤稿、独家等待、匿名或附件规则。

## 执行五项硬门禁

| 门禁 | 通过条件 | 未通过时 |
|---|---|---|
| 来源真实性 | 书目信息、原文位置、案号、数据来源可核验 | 标记待核、降级表述或删除 |
| 法律有效性 | 明确规范类型、版本、效力状态与核验日期 | 不作确定性现行法判断 |
| 引注完整性 | 来源性主张后有标识，正文、脚注与来源一一对应 | 不得交付最终稿 |
| 论证充分性 | 核心主张有理由、证据并处理重要反方观点 | 降为假说或补充论证 |
| 期刊适配 | 要求来自目标期刊正式来源并记录核验日期 | 保持通用工作稿状态 |

以下行为一律禁止：

- 编造作者、题名、期刊、出版社、年份、卷期、页码、DOI 或网址；
- 编造法律条文、效力状态、案号、法院、裁判日期、裁判观点、数据或调研结果；
- 把会议纪要、政策文件、案例、学术观点错误描述为法律或司法解释；
- 为满足字数或脚注数量而添加未阅读、未定位或不存在的材料；
- 删除待核标记并把未经核验的工作稿称为最终稿。

## 组织研究问题与论证

- 用一句话表述主问题，但允许设置有限子问题。
- 说明现有研究尚未充分解决的争议、缺口或解释困难；不强制同时存在理论与实务"双重空白"。
- 确认法律相关性，但允许法学与经济学、社会学、政治学、技术研究等交叉。
- 将研究范围压缩到可由现有材料和篇幅支持的程度。
- 区分作者主张、他人观点、法律文本、裁判观点、经验事实与推测。
- 对核心主张至少检查一个重要反方解释或反例。

不要用"已有三篇相似论文""必须三至四节""必须固定字数"等机械阈值代替学术判断。

## 建立论点—证据—引注链

整理材料时先使用 [source-register.md](assets/templates/source-register.md) 建立平台无关的来源登记；起草前再使用 [claim-evidence-matrix.md](assets/templates/claim-evidence-matrix.md)。每个核心主张记录：

- 主张及其在全文中的功能；
- 证据类型和来源编号；
- 原文页码、条文、段落或案例定位；
- 证据支持范围与局限；
- 反方材料；
- 核验状态；只有 `VERIFIED` 来源可以支持最终稿中的来源性主张。

没有足够证据的主张只能标为待证假说、缩窄表述或删除，不能通过修辞把证据缺口藏起来。

## 生成正文与引注

生成完整文章、章节或投稿稿件时，凡使用他人观点、原文、数据、案例、法律规范或其他非一般常识的外部事实，必须在对应句或段落后设置引注标识。不得只在文末罗列参考文献。

未指定期刊和输出格式时，Markdown 工作稿使用脚注标识：

```markdown
相关研究提出……。[^S001]

[^S001]: 作者：《题名》，载《期刊》年份第X期，第X页。
```

资料不完整时使用：

```markdown
相关研究提出……。[^待核引注-01]

[^待核引注-01]: [待核：缺少原文页码，不得进入最终稿]
```

直接引语必须有准确页码、条文号、段落号或其他可复核定位；转述同样需要来源。DOCX 投稿稿应转换为真实脚注或目标期刊指定格式。

## 区分工作稿与最终稿

### 工作稿可以包含

- `[待确认：目标期刊]`
- `[待核引注-01：缺页码]`
- `[待核案例-02：缺正式案号]`
- `[待核法条-03：需确认效力状态]`
- 明确标注的暂定结构或篇幅预算

### 最终稿必须满足

- 不含任何待核、待确认或虚构补全内容；
- 每项来源性主张均能反向追溯；
- 法律规范与案例身份经过核验；
- 直接引语定位完整；
- 目标期刊要求有正式来源；
- 题目、摘要、引言、正文与结论围绕同一主问题（一文一问）；
- 结论不超出正文已经证明的范围。

使用 [citation-audit.md](assets/templates/citation-audit.md) 和 [submission-checklist.md](assets/templates/submission-checklist.md) 完成最终检查。

## 常见错误

- 跳过启动纪律，未确认研究思路就摄入材料；
- 把背景介绍当作问题提出；
- 一篇论文塞多个问题（违反一文一问）；
- 按作者逐一罗列而不评价研究分歧；
- 只有材料和案例，没有可反驳的作者主张；
- 法条、案例与规范结论各说各话；
- 结语重复正文而不给出答案（违反 Q5）；
- 把资料的存在误当作资料已被核验；
- 把 Obsidian 内部链接直接当作正式引注；
- 把一般经验值写成所有 CSSCI 法学期刊的统一标准；
- 为迎合用户要求而补造引用信息。
- 用五问框架推演的结构替代用户既定的研究思路（五问是需求拆解工具，不是行文结构；先读用户的研究思路文档再生成大纲/评估初稿）。
