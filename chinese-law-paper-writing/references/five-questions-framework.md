# 五问框架（需求拆解基础方法）

## Overview

五问框架是**通用的需求拆解工具**（不限于法学，适用于用户任何研究/写作类需求）。当用户需求模糊、未说明研究思路时，AI用五个问题主动帮用户把模糊需求拆解为清晰的研究设计，再对照执行。

**定位区分（user confirmed 2026-08）**：
- **五问 = AI拆解用户需求的基础工具**（跨项目通用）。
- **三维度/任何具体行文思路 = 项目特定**（如群案研究三维分析框架仅适用于工伤认定群案研究项目），不是通用模板，新项目不得默认套用。
- 行文思路与需求拆解是两回事：行文思路是用户写作时组织文章的方式；五问是AI理解用户要什么的方式。

## When to Use

触发语义包括但不限于：

- "帮我写这个""我想做个研究""有个想法"（需求模糊，未说明方向/思路/素材）；
- 用户开始新研究项目，但没说研究/行文思路；
- 用户需求包含多个未知维度（要做什么/给谁用/解决什么问题/用什么资料/交付什么）；
- 用户说"你看看应该怎么做"而没有给出明确指令。

**核心纪律：用户没主动说研究/行文思路时，AI必须主动问，不得自行假设**（user confirmed 2026-08）。不要用上一个项目的思路套新项目。

## 五问内容（向用户提问的顺序）

1. **Q1 你要做什么？** — 研究主题、范围、问题领域（如：工伤认定群案研究）
2. **Q2 给谁用/给谁看？** — 读者定位、投稿期刊、用途（如：CSSCI论文/课程作业/内部报告）
3. **Q3 解决什么问题？** — 问题意识、核心论点（如：裁判偏差的系统性根源）
4. **Q4 基于什么资料？** — 素材、数据、文献来源（如：121案编译集/裁判文书网）
5. **Q5 交付成什么样子？** — 结构、篇幅、风格（如：1.5-2万字论文，类型化分析）

## 使用流程

1. **识别需求模糊度**：用户需求是否包含全部五问答案？缺哪个问哪个。
2. **主动提问**：一次问1-3个最关键的缺失项，不要一次抛5个问题淹没用户；用户回答后追问下一批。
3. **整理成研究设计**：用户回答完整后，AI把答案整理为清晰的研究设计（对照 `research-design/` 页面结构），再执行。
4. **用户也不知道思路时**：允许"先建库后定思路"——先把知识库/素材库建立起来，**在每个大模块完成后（MODULE-END CHECK时）主动帮用户更新研究思路、给出建议**（基于已摄入素材归纳可行的研究方向）。研究设计可以后置，但不能永远缺席——模块完成时主动提醒。

## 提问技巧

- 用大白话提问，避免学术黑话（用户偏好简短、分点）。
- 用户回答模糊时，给选项帮助确认（"是要A还是B？"）。
- 回答记录到研究设计页（若已有研究设计页则更新；没有则用户确认后创建）。

## 与其他skill的关系

- `legal-research-wiki`：法学建库skill，其研究设计页审计部分引用五问框架。
- `chinese-law-paper-writing`：法学写作skill，写作需求拆解引用五问框架。
- `llm-wiki`：底层通用Wiki方法论。
- 五问框架本身不依赖法学语境——任何研究需求都用它拆解。

## 常见陷阱

1. **用旧项目的行文思路套新项目**：三维度（群案研究）只适用于该项目，新项目必须重新问思路。
2. **一次问5个问题**：用户会被淹没，分批问（每次1-3个）。
3. **需求模糊时自行猜测**：猜错方向浪费大量工作——先问再动手。
4. **把五问当论文结构**：五问是拆解工具，不是论文行文结构（行文结构是项目特定思路）。
5. **用户不知道思路时硬要思路**：允许先建库，模块完成后主动给建议。

## Verification Checklist

- [ ] 用户需求是否已覆盖五问全部答案
- [ ] 未覆盖的是否已主动提问（而不是假设）
- [ ] 新项目是否没有套用旧项目思路
- [ ] 用户不知道思路时是否采用"先建库+模块后建议"路径
- [ ] 研究设计是否已整理并记录（研究设计页或用户确认后新建）
